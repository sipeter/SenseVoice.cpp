## 1. 步骤 5C-1：C++ 本机会话注册表

### 1.1 协议边界

PC 与 `ZianCore.exe` 继续使用父进程创建的重定向标准输入管道，不增加网络管理端口，也不把密钥放入进程命令行。登记指令固定为：

```text
LINK_V2_AUDIO_REGISTER <sessionIdHex32> <audioKeyHex64> <noncePrefixHex8>
LINK_V2_AUDIO_REMOVE <sessionIdHex32>
LINK_V2_AUDIO_CLEAR
```

- `sessionId` 是 RFC 4122 网络顺序的 16 字节 UUID，以 32 位十六进制传递。
- `audioKey` 固定 32 字节，nonce prefix 固定 4 字节。
- 字段数量、长度或十六进制字符不合法时拒绝整条指令，不改变已有登记。
- stdout 只返回不含标识和秘密的成功/拒绝状态；日志不输出密钥、nonce prefix 或完整登记命令。

### 1.2 实现

- 新增线程安全 `link_v2_audio_session_registry`，支持登记、覆盖、查找、撤销和全部清理。
- 覆盖、撤销、析构和 clear 时 best-effort 覆盖内存中的会话 ID、音频密钥和 nonce prefix。
- socket-only、dual-audio 及麦克风不可用后的 socket 降级路径均在原有 START/STOP 解析前处理登记命令。
- 原有 Link v1 START/STOP 和裸 PCM 接收行为保持不变；本步骤尚未启用 ZL2A 解密。

## 3. 步骤 5C-2：ZL2A 接收与解密

### 3.1 实现

- TCP 连接先累计至少 4 字节，再按首个 magic 固定为 Link v1 裸 PCM 或 Link v2 ZL2A；同一连接不允许切换格式。
- ZL2A 支持 TCP 分片与粘包，按固定 34 字节头、plainLength 和 16 字节 Tag 累计完整帧。
- 严格校验 magic、version、flags、非零且递增的 u64 序号、最大 65536 字节、偶数 PCM 长度和精确帧长。
- 仅接受 PC 管道已登记的 sessionId；使用登记的 audioKey、nonce prefix 和帧序号，通过 Windows CNG `BCrypt` 执行 AES-256-GCM。
- 完整 34 字节头作为 AAD；GCM 认证成功且注册表成功提交序号后才把 PCM16 写入 ring buffer。
- 未登记、重放/倒退、畸形长度和 Tag 失败均立即结束当前 TCP 连接；Tag 失败不推进序号。
- Link v1 裸 PCM 路径保持兼容，并修复跨 recv 的单个尾字节累计，避免奇数网络分片丢字节。

### 3.2 验证

- 使用 BouncyCastle 独立生成冻结 ZL2A 帧，C++ 测试逐字节解密为 `01000200ff7f0080`。
- 测试覆盖冻结帧、重放、Tag 篡改不推进序号、奇数 PCM 长度拒绝，以及此前注册表场景。

## 5. 步骤 5C-3：核心就绪确认

- REGISTER 成功后 stdout 返回 `[[LINK_V2_AUDIO_CONTROL_OK:<sessionIdHex>]]`；只包含非秘密 sessionId，不包含 key 或 nonce。
- PC 以该确认作为向手机发送 `AUDIO_SESSION_READY` 的唯一依据，手机在此之前不启动麦克风和 TCP 音频。
- REGISTER 拒绝仍只返回固定拒绝标记，避免回显畸形或敏感输入。
